# Общий блокнот

Одностраничный сайт на GitHub Pages: **один человек пишет текст и прикрепляет файлы — все,
кто открыл страницу, видят это сразу**, без перезагрузки.

Живой сайт: <https://dimidrol2252.github.io/>

GitHub Pages отдаёт только статические файлы, поэтому «общее» состояние хранится снаружи —
в Firebase Realtime Database. Текст лежит в узле `note`, файлы — в `filemeta` и `filedata`;
страница подписана на изменения и перерисовывается сама, новый посетитель получает
текущее состояние сразу при заходе.
Своего сервера не нужно, бесплатного тарифа Firebase хватает с запасом.

База: `https://notepade-share-default-rtdb.firebaseio.com` (проект `notepade-share`, регион us-central1).

## Как пользоваться

| Роль | Ссылка | Что делает |
|---|---|---|
| Редактор (ваш ПК) | <https://dimidrol2252.github.io/#admin> | видит поле ввода, публикует текст |
| Читатели | <https://dimidrol2252.github.io/> | видят текст живьём, редактировать не могут |
| Диагностика | <https://dimidrol2252.github.io/?diag=1> | состояние связи с базой и текст последней ошибки |
| Проверка сети | <https://dimidrol2252.github.io/check.html> | что вообще доступно из этой сети, включая Firebase |

Текст публикуется автоматически через ~0.8 с после того, как вы перестали печатать
(или сразу по кнопке «Опубликовать»). Панель диагностики открывается и по клику
на индикатор связи в правом верхнем углу.

## Файлы и скриншоты

Редактор прикрепляет файлы тремя способами: кнопкой, перетаскиванием в любое место
страницы и вставкой скриншота из буфера по `Cmd+V`. Читатели видят сетку превью;
клик по картинке открывает её в полном размере, клик по файлу скачивает его.
Удалять может только редактор — файл пропадает у всех.

Как это устроено:

- **Превью и содержимое лежат в разных узлах.** В `filemeta` — имя, размер, время
  и маленькое превью; в `filedata` — сам файл в base64. Страница при загрузке тянет
  только `filemeta`, а содержимое качается по клику. Иначе каждый заход стягивал бы
  все файлы разом.
- **Картинки сжимаются в браузере** до 1600 пикселей по длинной стороне и пережимаются
  в WebP. Тестовый PNG на 2400×1400 весом 3 МБ превратился в 17 КБ. Оригинал на диске
  не трогается, ужимается только копия для передачи.
- **Предел — 5 МБ на файл** после сжатия: узел базы держит 10 МБ, а base64 раздувает
  файл примерно на треть.
- Остальные файлы уходят как есть, байт в байт.

Расход бесплатного тарифа: 1 ГБ хранилища и 10 ГБ трафика в месяц. Каждый читатель
скачивает файл заново, так что для скриншотов по 100–300 КБ это десятки тысяч просмотров.

## Требования к сети

Firebase работает по 443 порту и проходит через закрытые корпоративные сети.
Проверить конкретную сеть можно страницей [check.html](https://dimidrol2252.github.io/check.html) —
она стучится к настоящим хостам и показывает, что доступно.

**База должна быть в регионе us-central1.** Тогда её адрес заканчивается на `.firebaseio.com`.
Базы европейского и азиатского регионов живут на домене `firebasedatabase.app`, а он
в закрытой сети, где проверяли, оказался заблокирован.

Если WebSocket до Firebase не проходит, библиотека сама переключается на обычные
HTTPS-запросы — будет чуть медленнее, но работать будет.

## Правила базы

**Realtime Database → Rules:**

```json
{
  "rules": {
    "note": {
      ".read": true,
      ".write": true
    },
    "filemeta": {
      ".read": true,
      ".write": true
    },
    "filedata": {
      ".read": true,
      ".write": true
    }
  }
}
```

Читать и писать может кто угодно, но только эти три узла — остальная база закрыта.
Ссылка `#admin` не защита, а переключатель режима: кто угодно может дописать её
к адресу и получить поле ввода. Если понадобится ограничить запись, заведите
в Authentication пользователя с паролем и замените правило записи на
`"auth != null && auth.uid === 'ваш-uid'"`, а на странице добавьте форму входа.

## Настройка своей копии

В `index.html` вверху скрипта:

```js
const firebaseConfig = {
  projectId: "notepade-share",
  databaseURL: "https://notepade-share-default-rtdb.firebaseio.com"
};
```

Больше ключей не нужно: без авторизации библиотеке хватает адреса базы, а доступ
ограничивают правила, а не секретность конфига.

## Что важно понимать про ограничения

- **Писать может любой, кто открыл `#admin`** — так выбрано сознательно. Для доски
  объявлений нормально, для чего-то ответственного нужна авторизация (см. «Правила базы»).
- **Не публикуйте пароли и личные данные** — и текст, и файлы читает кто угодно, зная адрес базы.
- Бесплатный тариф Firebase (Spark) — 1 ГБ хранилища и 10 ГБ трафика в месяц.
  Для текстового блокнота это недостижимо много.
- Размер текста лучше держать в пределах нескольких сотен килобайт.

## Разработка

```bash
python3 -m http.server 8000
```

Откройте `http://localhost:8000/?diag=1#admin` в одном окне и `http://localhost:8000/` в другом.
Обе копии работают с той же боевой базой.

Публикация изменений — обычный push, Pages пересобирается за минуту:

```bash
git add -A && git commit -m "..." && git push
```
